  Next.js configuration: output standalone (for Docker), experimental settings,
  environment variable passthrough.

  ESLint 9 flat config using eslint-config-next for code quality rules.

webapp/postcss.config.mjs
  PostCSS configuration enabling Tailwind CSS 4 processing.

webapp/playwright.config.ts
  Playwright E2E test configuration. Spawns backend (run-playwright-backend.sh)
  and webapp (run-playwright-webapp.sh) as webServer dependencies. Uses 1 worker
  (fullyParallel: false), 60s timeout, retains trace on failure. Locally targets
  https://localhost:3443; in CI targets http://127.0.0.1:3001.

webapp/Dockerfile
  Multi-stage Docker build. Stage 1 (deps): npm ci. Stage 2 (check): lint +
  build. Stage 3 (runner): production standalone server with TLS scripts.
  Entry: node scripts/serve-production-https.mjs.

webapp/.dockerignore
  Files excluded from Docker build context (node_modules, .next, test artifacts).

webapp/.gitignore
  Git ignores for Next.js (.next/, node_modules/, test-results/, etc.).

================================================================================
WEBAPP SCRIPTS
================================================================================

webapp/scripts/serve-standalone-https.mjs
  Development HTTPS server. Generates a self-signed TLS certificate via openssl
  (stored in .local-https/), then launches next dev on port 3000 and an HTTPS
  proxy on port 3443. Used by `npm run dev`.

webapp/scripts/serve-production-https.mjs
  Production HTTPS server. Loads TLS certificate from .local-https/ (or generates
  a new one), then runs the Next.js standalone server on port 3000 with an HTTPS
  proxy on port 3443. Used by `npm start` and the Docker image. Respects
  HTTPS_HOSTS and HTTPS_IPS env vars for certificate SAN coverage.

webapp/scripts/local-https.mjs
  Shared TLS certificate management. Generates self-signed certificates with
  Subject Alternative Names (SANs) covering localhost, configured hosts, and IPs.
  Used by both serve-standalone-https and serve-production-https.

webapp/scripts/discovery-smoke.cjs
  LAN discovery smoke test script. Scans common LAN addresses to verify the
  server's /health endpoint is reachable from the browser. Used for manual
  debugging of the discovery flow.

WEBAPP SOURCE (webapp/src/)

--- Middleware ---

webapp/src/proxy.ts
  Next.js middleware (edge). Enforces HTTPS: if ALLOW_INSECURE_HTTP is not set,
  redirects all HTTP requests to HTTPS (308 Permanent Redirect). Sets HSTS
  header on secure connections. Matches all routes except static assets.

--- App Router Pages ---

webapp/src/app/layout.tsx
  Root layout. Wraps all pages with ThemeProvider, AuthProvider, LanguageContext,
  ToastContext, and the Sidebar + MQTT warning banner. Sets HTML lang attribute,
  meta viewport, and favicon.

webapp/src/app/page.tsx
  Dashboard home page. Renders device cards grouped by area/room using
  visibility-based filtering. Connects to WebSocket for live device state updates.
  Includes area/room switcher and device quick-control (on/off, brightness).

webapp/src/app/login/page.tsx
  Login page. Username + password form, JWT token acquisition, redirect to
  dashboard on success. Shows error states for invalid credentials and
  server unavailability.

webapp/src/app/register/page.tsx
  Registration page placeholder. In the current baseline, only admins create
  users — this page is conditionally shown during initial setup or admin flow.

webapp/src/app/setup/page.tsx
  Initial server setup wizard. Creates the first admin account + household
  atomically. Only accessible when the server is uninitialized (no users exist).
  Blocks re-initialization after successful setup.

webapp/src/app/devices/page.tsx
  Device inventory page. Lists all devices with filtering by area, auth status
  (pending/approved/rejected), and online state. Each device card shows type,
  room, last seen, and quick actions.

webapp/src/app/devices/diy/page.tsx
  DIY flasher page. Multi-step wizard (Step 1: board selection → Step 2: pin
  mapping → Step 3: validation → Step 4: build & flash). Orchestrates the
  server-side build pipeline and browser-side Web Serial flash.

webapp/src/app/devices/discovery/page.tsx
  Device discovery page. Shows pending devices awaiting admin approval, with
  device identity, capabilities, and approve/reject buttons.

webapp/src/app/devices/[id]/config/page.tsx
  Per-device configuration page. Shows device identity, pin configuration,
  assigned Wi-Fi credential, OTA update controls, serial monitor, and
  device reconfiguration options.

webapp/src/app/devices/pro-code/page.tsx
  Pro-code device page. Advanced interface for developers — shows raw device
  state, MQTT topics, command history, and debug tools.

webapp/src/app/automation/page.tsx
  Automation list page. Shows all automation rules with enable/disable toggles,
  last execution status, and quick-create button.

webapp/src/app/automation/[id]/page.tsx
  Automation editor page. Visual rule graph builder where users connect
  trigger nodes (device state, time, sensor threshold) → condition nodes
  (AND/OR/comparison) → action nodes (set output, send command).

webapp/src/app/extensions/page.tsx
  Extension management page. Lists installed extensions with card type, status,
  and controls to upload new extensions (ZIP), enable/disable, or uninstall.

webapp/src/app/extensions/[id]/page.tsx
  Extension detail page. Shows extension metadata, supported capabilities,
  configuration fields, and devices using this extension.

webapp/src/app/logs/page.tsx
  System logs viewer. Displays server logs with filtering by category (health,
  auth, device, firmware, automation), severity, and date range. Real-time
  updates via WebSocket.

webapp/src/app/settings/page.tsx
  Settings dashboard. Tabbed interface with panels: Wi-Fi credentials
  (WifiCredentialsPanel), API keys (ApiKeysPanel), configs (ConfigsPanel),
  general settings (timezone, household location, language).

webapp/src/app/settings/WifiCredentialsPanel.tsx
  Wi-Fi credential vault UI. Admin-only: create, edit, delete SSID/password
  entries. Passwords are masked; reveal requires re-entering account password.
  Lists credentials used by devices and DIY projects.

webapp/src/app/settings/ApiKeysPanel.tsx
  API key management UI. Create, copy, revoke API keys for programmatic access.
  Shows creation date, last used, and status.

webapp/src/app/settings/ConfigsPanel.tsx
  Config history panel. Lists saved DIY project configurations with rename and
  delete actions.

webapp/src/app/settings/SvgPinMapPreview.tsx
  SVG pin map preview component. Renders an interactive SVG of a board pinout
  with colored highlights for assigned/available/conflicting pins.

webapp/src/app/favicon.ico/route.ts
  Favicon route handler — serves the app icon.

webapp/src/app/globals.css
  Global CSS: Tailwind directives (@import "tailwindcss"), CSS custom properties
  for theming (light/dark mode colors), base element styles.

webapp/src/app/icon.svg
  SVG app icon used as favicon.

webapp/src/app/api/diy/demo-firmware/[board]/[artifact]/route.ts
  API route that proxies firmware artifact requests to the backend server.
  Handles dynamic board/artifact path segments for demo firmware downloads.

--- DIY Flasher Feature ---

webapp/src/features/diy/types.ts
  TypeScript type definitions for the DIY flasher feature: FlashManifest,
  FlashSource, BuildJobStatus, PinAssignment, BuildArtifact, etc.

webapp/src/features/diy/board-profiles.ts
  Board profile definitions for all supported ESP32/ESP8266 variants. Each
  profile defines: chip family, flash size, GPIO pin list with labels and
  constraints (input-only, ADC-capable, boot-sensitive, reserved), default
  I2C pins, and SVG image reference. Returns sorted GPIO arrays for the
  interactive pin mapping grid.

webapp/src/features/diy/validation.ts
  Client-side DIY config validation. Checks GPIO conflicts (shared pins between
  components), reserved/boot pin violations, I2C bus address conflicts,
  capability-mode mismatches (e.g., analog pin used for digital output).
  Mirrors server-side validation for instant feedback.

webapp/src/features/diy/project-board.ts
  Project-board state management. Manages the current DIY project's board
  selection, pin assignments, I2C device list, and Wi-Fi credential choice.
  Persists to server via API.

webapp/src/features/diy/managed-config-sync.ts
  Config synchronization for managed (already-deployed) devices. Compares
  server-side config with local edits, detects drift, handles merge conflicts
  when reconfiguring a device that was previously built via DIY flasher.

webapp/src/features/diy/flash-manifest.ts
  Flash manifest builder. Constructs the ESP Web Tools flash manifest (array
  of {address, data} entries) from server build artifacts. Calculates flash
  offset addresses per chip family (ESP32: 0x10000 app, 0x8000 partitions,
  0xE000 boot_app0; ESP8266: different layout). Generates the manifest used
  by the Web Serial flasher to write firmware to the board.

webapp/src/features/diy/components/Step1Board.tsx
  Step 1: Board selection. Grid of board cards with chip image, name, and
  specs (flash size, GPIO count). User selects target ESP32/ESP8266 variant.

webapp/src/features/diy/components/Step2Pins.tsx
  Step 2a: GPIO pin mapping. Interactive SVG overlay on the board pinout image.
  User clicks GPIO pins to assign them to components (LED, relay, sensor, I2C).
  Color-coded: green=assigned, red=conflict, yellow=reserved, gray=available.
  Real-time validation feedback.

webapp/src/features/diy/components/Step2Configs.tsx
  Step 2b: Component configuration. For each assigned component, configures
  parameters (pin mode: input/output/input_pullup, I2C address, device type).
  Also selects Wi-Fi credential from vault and sets device name.

webapp/src/features/diy/components/Step3Validate.tsx
  Step 3: Validation summary. Shows full pin map preview (SVG) with all
  assignments, component list, selected Wi-Fi network, and any warnings/errors.
  Block build button if config has unresolved conflicts.

webapp/src/features/diy/components/Step4Flash.tsx
  Step 4: Build & flash. Sends config to server → monitors build job via
  WebSocket (queued → building → artifact_ready) → downloads firmware artifact
  → initiates Web Serial flash using ESP Web Tools. Shows build log output,
  flash progress bar, and success/failure state.

--- Hooks ---

webapp/src/hooks/useWebSocket.ts
  WebSocket hook. Connects to the server's WebSocket endpoint, handles
  reconnection with exponential backoff, parses incoming JSON events, dispatches
  to registered handlers by event type (device_state, build_progress,
  system_metrics, serial_output, mqtt_status).

webapp/src/hooks/useOtaUpdate.ts
  OTA update hook. Manages firmware version comparison, update trigger,
  progress tracking, and rollback logic.

--- Library Modules ---

webapp/src/lib/api.ts
  Core API client. Constructs fetch requests to the backend with auth headers
  (JWT Bearer token), handles response parsing, error normalization, and
  retry logic. Exports typed functions: getDevices, getAutomations, sendCommand,
  etc. Resolves API base URL from NEXT_PUBLIC_API_URL env var.

webapp/src/lib/auth.ts
  Authentication utilities. Token storage (localStorage with fallback), token
  decoding (JWT claims extraction), token expiry check, logout cleanup.
  Provides getToken/setToken/removeToken used by api.ts and AuthProvider.

webapp/src/lib/api-keys.ts
  API key management API client. Functions for create/list/revoke API keys,
  with typed request/response interfaces.

webapp/src/lib/api-automation.ts
  Automation API client. CRUD operations for automation rules, trigger execution,
  execution log retrieval.

webapp/src/lib/automation-utils.ts
  Automation graph utilities. Node/edge manipulation helpers, graph validation
  (detect cycles, dangling edges, incompatible port types), default graph
  templates for common patterns (motion sensor → light, temperature → fan).

webapp/src/lib/device-config.ts
  Device configuration utilities. Parses and normalizes device config payloads,
  maps between UI state and API models for pin configurations, capability
  declarations, and Wi-Fi credential assignments.

webapp/src/lib/device-display.ts
  Device display name and icon resolution. Maps device types and capabilities
  to human-readable labels and Material Design icons for the dashboard cards.

webapp/src/lib/rooms.ts
  Room management API client. CRUD for rooms, room-device assignment,
  room-based visibility filtering.

webapp/src/lib/wifi-credentials.ts
  Wi-Fi credential API client. CRUD for credentials, masked list display,
  password reveal flow (requires account password re-authentication).

webapp/src/lib/secure-origin.ts
  Secure origin resolution. Determines the correct API base URL considering
  HTTPS vs HTTP, forwarded headers, and Docker internal networking. Builds
  provisioning headers for device handshake requests.

webapp/src/lib/home-location.ts
  Household location utilities. Geocoding (address → coordinates), reverse
  geocoding (coordinates → address), map view state management.

webapp/src/lib/i18n.ts
  Internationalization. Translation dictionary (en/vi) for all UI strings,
  dynamic locale detection, number/date formatting.

webapp/src/lib/server-time.ts
  Server time utilities. Fetches server timezone offset, formats timestamps
  in server-local time for display consistency.

webapp/src/lib/system-log.ts
  System log API client. Log retrieval with category/severity/date filtering,
  log acknowledgment, real-time log streaming via WebSocket.

--- Type Definitions ---

webapp/src/types/device.ts

webapp/src/types/automation.ts
  Automation type definitions: graph node/edge types, trigger types

webapp/src/types/esp-web-tools.d.ts
  TypeScript declaration file for the ESP Web Tools library (Web Serial flashing).

WEBAPP E2E TESTS (webapp/tests/)

webapp/tests/support/e2e.ts

  E2E: WebSocket real-time update test. Verifies that device state changes
  pushed via WebSocket are reflected in the UI without page refresh.

webapp/tests/board_reserved_sync.spec.ts
  E2E: Reserved pin synchronization. Verifies that reserved/boot-sensitive pins
  shown in the UI match the board profile definitions and are correctly blocked.

  Serial flashing has correct addresses, sizes, and artifact references per
  board family.

webapp/tests/managed_config_sync_state.spec.ts
  E2E: Managed config sync. Verifies that reconfiguring a previously-built
  device correctly syncs config state between server and UI.
